# S1 — Full レンダラの最小試作

設計書 §17 Phase 0 の S1。GTK 4.22 のウィジェットが、**自分の中身の上に既存拡張の `glass.frag` をそのまま描けるか**を確かめる。
描くのは同じフレームの中身で、十分に速いことが条件。

- 使っているシェーダ: 既定は **シェーダ Core**（`shaders/core`、S5 で参照とビット単位で一致を確認。glass-lib と同じ写像）。
  `--reference`（`R` キー）で、参照 `shaders/reference/glass.frag`（拡張の出荷版の無改変コピー）を仮想キャンバス上で描く方式に切り替わる。
- 仕組み: 設計書 §7・§8 のとおり。`s1-glass-view.c` の先頭のコメントに流れをまとめてある。

## 実行

```bash
meson setup build          # 初回だけ
meson compile -C build
./build/spikes/s1-full-renderer/glass-s1 --autoscroll
```

| オプション | 意味 |
|---|---|
| `--autoscroll` | 中身を 900px/s で往復スクロールし続ける（計測用） |
| `--no-cache` | 毎回取り込み直し・描き直す |
| `--private-renderer` | 取り込みに窓のレンダラではなく専用の `GskRenderer` を使う |
| `--no-glass` | ガラスなしで開始（A/B 用） |
| `--blur-radius=PX` | ぼかし半径（既定 3。拡張のドックは 5） |
| `--downscale=2\|4` | 取り込みの縮小率（既定 2） |
| `--debug-view=0\|1\|2` | `glass.frag` のデバッグ表示（1 = 形状と影のマスク） |
| `--preset=NAME` | 縁のプリセット: `crisp`（既定）・`crisp-strong`・`crisp-soft`・`thinner`・`extension`（拡張の値）。値は `docs/memo.md` 追記5 |
| `--param NAME=VALUE` | 光学パラメータを 1 つ上書き（繰り返し可。例 `--param rim_width=2`） |
| `--sweep=DIR --candidate NAME:K=V,... [--sweep-scroll=A,B,...]` | 候補ごとの見た目を、同じ窓の中で順に描いてパネルの周りを保存する（比較用）。`K` は光学パラメータのほか `ss=0\|1`・`rim=N`・`fp=0\|1`・`fph=PX`・`blur=PX` |
| `--screenshot-panel` | 画面の保存を上のパネルの周りだけに切り出す |
| `--reference` | 参照シェーダ（無改変）で描く。既定は Core |
| `--no-supersample` | 1 画素 1 サンプル（拡張と同じサンプリング）。既定は RGSS 4 サンプル |
| `--estimated-footprint` | レンズのフットプリントを参照の解析式で見積もる（これまでの方式）。既定は測ったフットプリント（`lens_footprint_px`） |
| `--rim-samples=N` | 縁の帯（内側 8px まで）だけ 1 画素 N サンプル（比較・正解画像づくり用。既定 0 = 使わない） |
| `--shadow-radius=PX` / `--shadow-intensity=X` | 影（アプリ内の既定 16px・0.20。拡張は 30px・0.55） |
| `--capture-full` | 全解像度で取り込み、GL で 2x2 ボックス縮小（拡張と同じ取り込みの経路。比較用） |
| `--scroll-to=PX` | 起動時のスクロール位置（比較用の画面保存に） |
| `--pulse` | 上のパネルの星だけを 10 回/秒描き直す（前景だけが変わる場合の確認） |
| `--quit-after=SEC` / `--screenshot=FILE` / `--screenshot-at=SEC` | 自動終了・画面の保存 |

キー操作: `Space` ガラスの ON/OFF、`C` キャッシュの ON/OFF、`D` デバッグ表示の切り替え、`A` 自動スクロールの ON/OFF、
`S` スーパーサンプリングの ON/OFF、`H` 影をアプリ内の値 ⇔ 拡張の値で切り替え、`R` Core ⇔ 参照シェーダ、
`E` 縁のプリセット（crisp → crisp-strong → crisp-soft → thinner → extension）、
`F` 測ったフットプリント ⇔ 参照の見積もり、`B` ぼかし半径（2 → 3 → 4 → 5）。

レンダラの切り替え: `GSK_RENDERER=vulkan|gl`、X11: `GDK_BACKEND=x11`。

毎秒 1 行、次の値を表示する: fps、snapshot 数、ガラスのパス数、取り込み数、キャッシュの当たり、snapshot あたりのガラスの CPU 時間、取り込み 1 回あたりの内訳。

|---|---|---|---|
| Wayland・Vulkan（既定）・スクロール中 | 60.0 | 1.41〜1.51 ms・最大 3.45 ms | render_texture 0.43〜0.48 / download 0.13〜0.14 / upload 0.01 / GL 0.11 ms |
| Wayland・GL・スクロール中 | 60.1 | 1.39〜1.41 ms・最大 2.66 ms | 0.40 / 0.18 / 0.01 / 0.09 ms |

### Go の基準との照合

| 基準（設計書 §17） | 結果 |
|---|---|
| (1) 中身とガラスのずれが 0 フレーム | ✅ 構造上保証（同じ snapshot の同じノードから作る）。スクロール中の画面保存でも一致。**ユーザーの目視でも問題なし**（2026-09-24。リサイズも正常） |
| (2) 60fps | ✅ すべての条件で 60fps |
| (3) 追加の CPU ≤ 3ms/frame | ✅ 平均 1.4〜1.5 ms（パネル 2 枚）。最大は 2.4〜3.5 ms |
| (4) Vulkan と GL の両レンダラで動く | ✅（GL は下記の不具合を直してから） |
| (5) snapshot 中の `render_texture` が安全 | ✅ 両レンダラで警告・破綻なし。専用レンダラ（`--private-renderer`）は不要。性能も同じ |

### 途中で見つけた不具合（`docs/memo.md` 地雷1）

GTK の GL レンダラでは、`gsk_renderer_render_texture()` と `GdkTextureDownloader` が**GTK 側の GL コンテキストを current にしたまま戻る**。
続く自前の GL 呼び出しが GTK のコンテキストで実行され、FBO と VAO（コンテキスト間で共有されない）が別物になった。
その結果、ガラスが 2 倍に拡大された左上の断片として表示された。取り込みの後に自分のコンテキストを current にし直して解決した。

### ユーザー確認後の修正（2026-09-24、`docs/memo.md` 追記2）

ユーザーの確認では、スクロール追従とリサイズは問題なかった。指摘は「影が強い」と「縁のジャギーが多く、縁の見た目が拡張より悪い」の 2 点。

- **縁**: 取り込みの解像度（`--capture-full` と比べて差は最大 7/255）と、合成の色空間（GTK も sRGB 空間）は原因ではなかった。
  原因は `glass.frag` を 1 画素 1 サンプルで評価していること。**RGSS 4 サンプルのスーパーサンプリング**を既定にした。
  `glass.frag` は変えず、`main()` を関数に改名して包む（`shaders/targets/compat/cogl_postlude.glsl`）。
  コストは CPU で変化なし、GPU busy% がスクロール中に 8% → 9〜10%。
- **影**: 式は拡張と同じで、値が壁紙の上のドック向けだった。アプリ内の既定を **16px・0.20** に下げた（比較して選んだ初期値）。

### まだ確かめていないこと

- 分数スケール・2x（このマシンは 1x）
- dGPU（読み出しが遅い可能性）

### ユーザー確認後の修正 2（2026-09-25、`docs/memo.md` 追記5）

指摘は「縁は thinner がよいがガラス感は残す」「thin では屈折した細かい模様が縁でジャギーになる」「4x の方がジャギーは少ない」「ぼかし半径を小さく」。

- **ジャギー**: 縁の 1〜3px 内側で、1 画素が元の約 50px を掃く（「崖」）。参照のフットプリントの見積もりはその 4〜15 分の 1 だった。
  さらに縁ちょうどで屈折が不連続に 0 になる。Core に**測ったフットプリント**（`lens_footprint_px`）を足した（参照の経路は `0` で不変、ゴールデン 0/255）。
  256 サンプルの正解に対する最大誤差は 39〜63 → 14〜26、GPU busy% は +1 ポイント。
- **取り込み範囲**: 薄いパネルでは、レンズが反対側の縁の先を読む。取り込みに `max(0, 96 − min(w, h))` を足した（地雷10）。
- **縁のプリセット**: 線（輪郭のぼかし・リムの光・内側の影・色のにじみ）は thinner の値で、レンズは拡張のドームの形のまま、強さ 3 段階（`crisp` が既定）。
- **ぼかし半径**: 既定 5 → 3。
- 計測（既定の設定、スクロール中、パネル 2 枚）: 60fps、CPU 1.5〜1.9 ms/フレーム、GPU busy% はガラスなしとの差 4〜5 ポイント。
